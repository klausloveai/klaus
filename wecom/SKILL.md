# 企业微信（WeCom）Mac 操作

企微没有给普通账号读聊天记录的接口，本地数据库也是加密的（不要尝试破解）。这个技能靠模拟键盘、滚轮和截图来操作客户端，你通过读截图拿到聊天内容。

## 本机修补（相对 Joe 2026-10-15 原版）

- `raise_main` 改成 `activate` 并确认企微到了最前面；每次按键前也再核一次，前台不是企微就退出，按键不会打进别的程序（原版在这台 Mac 上会把 ⌘A / ⌘V 打进 Chrome）。退出时剪贴板照样还原。
- `setup` 的 swiftc 编不过时自动改用 clang 编 `scripts/scroll.c`（CLT 的 Swift 6.1 配不上 macOS 26.2 SDK）。
- 默认聊天区域按这台 Mac 实测：左 493、顶 64、右 183、底 229pt。
- capture 拼图只缩不放：企微在 1x 外接屏上时截图本来就窄，放大会糊。
- 企微窗口会在主屏和左侧副屏（负坐标）之间换，坐标每次现取，不要沿用上一次的数。

所有命令都在本技能目录的 `scripts/wecom.sh`，下面的 `W` 指 `zsh <技能目录>/scripts/wecom.sh`（用 zsh 调用，不依赖文件的可执行权限）。

## 第一次使用

1. 运行 `W setup`，按提示补齐：
   - **辅助功能**：系统设置 → 隐私与安全性 → 辅助功能，打开**小写的 claude**（灰色图标）。大写橙色的 Claude 是桌面 App，只开它不够。
   - **屏幕录制**：同一页面里的「屏幕录制」，也打开小写的 claude。
   - **ImageMagick**：`brew install imagemagick`
   - 系统设置只能由用户自己打开，你可以用 `open "x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility"` 把页面打开给他看。
2. 运行 `W bounds`，再 `W shot /tmp/check.png`，看截图是不是正好框住聊天消息区（不含左边会话列表、右边成员栏、底部输入框）。不对就自己算一个 `x,y,宽,高` 区域，后面的 shot/capture 都带上这个参数。

## 打开一个群

```
W search "Nova"
```
然后**截图看搜索结果**，确认排第一的就是目标群，再 `W open`。企微搜索会匹配聊天内容，排第一的经常是别的客户群。不是第一条时让用户手动点，或者先换更完整的群名再搜。打开后再截一次图，核对顶部群名。

## 归档聊天记录到 Drive

1. 打开群，核对群名。
2. `W capture /tmp/wecom/<群名>`。它会先滚到底，再一屏一屏往上滚到顶并截图，最后拼成 `strip_00.png`（最早）到 `strip_NN.png`（最新）。期间用户不能动企微窗口，开始前告诉他一声。
3. 先看 strip_00 和 strip_01 的接缝，确认两屏之间有重叠、没漏字。漏了就把步长调小重来：`W capture <目录> "" 14`。
4. 按顺序读所有 strip，整理成 Markdown 文字记录：
   - 开头写群名、案件、时间范围、整理日期、群成员。
   - 按日期分节，每条写「**时间 发送人**：原文」。原文照抄，不改写、不总结。
   - 引用回复写成「（引用 XX）」。撤回的消息写 [XX 撤回了一条消息]。语音写 [语音 N 秒]，转不了文字。
   - 图片只写一句摘要，比如 [图片] 支票正面。**护照号、身份证号、银行账号、卡号一律不转录。**
   - 企微自动翻译的那一行不用记，只记原文。
   - 末尾列一张表：群里发过的所有文件（日期、发送人、文件名、大小）。
5. 找到这个客户在 Drive 的案卷文件夹（问用户，或在 `~/Library/CloudStorage/GoogleDrive-*/Shared drives/` 下按客户名找），在案卷根目录建 `WeCom 聊天记录/`，放进去：
   - `<群名> 聊天记录 <起始日期> 至 <结束日期>.md`
   - `原始截图/`：所有 strip，方便以后核对
   - `附件/`：群里的文件（见下一节）
6. 写完后告诉用户放在哪，并说明哪些没归档（没下载过的文件、语音、撤回的消息）。

## 群里的文件

企微下载过的文件以原文件名存在本机缓存里：
```
W files "应诉方案"
```
同名文件可能有好几份，按大小和日期挑和群里那条对上的。复制到 `附件/` 时文件名前加发送日期，比如 `2026-09-28 Nova Space 应诉方案.pdf`。本机找不到的文件（没点开下载过），列给用户，问要不要在企微里点下载，不要自己去点。案卷里已经有的同一份文件，也照样放一份进 `附件/`，保留群里的原名。

## 写回复草稿

1. 先读这个群最近的聊天（`W shot` 截一屏，或用归档好的记录），需要的话读案卷材料。
2. 草稿写进一个临时文本文件，在对话里给用户看一遍。
3. 打开群、截图核对群名，然后 `W paste 草稿.txt`。要配图用 `W paste-image 图片.jpg`。
4. 用 `W read-input` 读回输入框内容，确认没有残留的旧文字。
5. 截图给自己核对，然后告诉用户「已经放进输入框，没有发送」。

### 回复怎么写

- 中文口语、简短，跟律所同事平时在群里的说法一样。称呼照群里已有的叫法（王总、Fallon 您好）。
- 期限、金额、案号、律师意见必须和案卷或律师的指示一致，查不到的不写，先问用户。
- 信用卡授权、证件、银行信息这类私密材料不在群里要，请客户私信发。
- 涉及法律判断或给客户建议的内容，发之前要用户（或主办律师）确认。
- 已经在邮件里发过的东西，写清楚是哪天、发到哪个邮箱、标题是什么，需要时配邮件截图。

## 发送

**只有用户在对话里明确说「发送」「发」才执行 `W send`。** 发之前先 `W read-input` 确认输入框内容就是用户同意的那一版、群名没错。发完截图确认消息出现在群里。用户之前同意过一次，不代表下一条也可以直接发。

## 注意

- 这些操作会占用企微窗口和剪贴板（脚本会恢复剪贴板的文字内容）。用户正在打字时不要操作。
- 截图里的内容都是客户资料，只存进律所的 Drive 案卷，不要发到别处。
- 测试时只用内部群（没有「外部」标签的群），别往客户群里贴测试文字。
- 企微改版后快捷键或布局可能变化，出问题先截图看实际界面。
