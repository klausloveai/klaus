# Field map — ETA-9089 Appendix A, Appendix C, Final Determination

These three are **Department of Labor** forms, not USCIS ones. Edition
**Expires 02/28/2029**, OMB 1205-0451, verified 2026-08-24 by download and by
rendering every page. Re-verify with
`forms.py fetch eta-9089-appA eta-9089-appC eta-9089-final`.

| Piece | Pages | Fields | URL |
|---|---|---|---|
| Appendix A — Foreign Worker Information | 5 | 114 | `dol.gov/sites/dolgov/files/ETA/oflc/pdfs/ETA-9089-AppendixA-Expires02-28-29.pdf` |
| Appendix C — Supplemental Information | 1 | 6 | `…/ETA-9089-AppendixC-Expires02-28-29.pdf` |

## Why an NIW files a labor-certification form at all

An NIW is a **waiver** of the job offer and of the labor certification, so there
is no PERM case, no DOL case number and no certification. What USCIS still wants
with the I-140 is the ETA-9089 **uncertified**, as the document that describes the
beneficiary's education, experience and the job — which is why the firm's NIW
Checklist lists Appendix A, Appendix C and the Final Determination as part of
every package, and why I-140 page 3 items 9 and 10 are still **No**.

Practical consequences:

- **Page 1 of the Final Determination is DOL-use-only and stays entirely blank** —
  DOL Case Number, Case Status, Employer FEIN, Filing/Determination/Expiration
  dates, the OFLC electronic signature. Do not invent a case number. Both stored
  Final Determinations leave page 1 empty.
- Only **page 2** of the Final Determination gets filled, and only its
  signature blocks.
- Nothing here goes to DOL. The whole set travels in the USCIS envelope.

## The edition trap: field names changed between editions

The firm's already-filed Appendix A copies are on the **Expires 10-31-2025**
edition, and **75 of its field names differ from the current edition** — the old
names carry an extra `Enter`:

| Current (Expires 02-28-29) | Old (Expires 10-31-2025) |
|---|---|
| `1  Foreign Workers Last family Name` | `1 Enter Foreign Workers Last family Name` |
| `11  Date of Birth mmddyyyy` | `11 Enter Date of Birth mmddyyyy` |
| `10  Province` | `10 Enter Province` |

**Appendix C and the Final Determination did not change** — their field-name sets
are identical between the older filed copies and the current download.

So: never copy an Appendix A field name out of an older filing. Derive it from
the freshly downloaded blank with `forms.py dump`. `fetch` reports when the file
that arrives disagrees with the edition it asked for, but it cannot check what DOL
currently publishes — dol.gov 403s its own HTML pages from this Mac, so somebody
has to open the forms page in a browser and look. See the environment notes in
`fees-and-filing.md`.

Field names on these forms are the **printed label flattened**, with punctuation
stripped and doubled spaces where the label had a number-and-period. They are
long, they contain spaces, and several differ only by a trailing `_2` / `_3`.
Quote them exactly in the values JSON.

### Section B — Education, five blocks (pages 1–2)

Each block is one degree: a checkbox row for the level, then 1a–1e.

| Block | Degree checkboxes (all `on=/On`) | 1a other | 1b majors | 1c institution | 1d country | 1e mm/yyyy |
|---|---|---|---|---|---|---|
| **a** (p1) | `None` `High SchoolGED` `Associate` `Bachelors` `Master` `Doctorate PhD` `Other Degree JD MD etc` | `1a If Other Degree in question 1 specify the diplomadegree attained` | `1b  Specify majors andor fields of study may list more than one related major and more than one field` | `1c  Name of Institution that issued the degreediploma` | `1d  Name of Country of institution identified in question 1c` | `1e  Monthyear attained mmyyyy` |
| **b** (p1) | same names + `_2` | `…attained_2` | `…and more than one field_2` | `…degreediploma_2` | `1d  Name of Country of Institution identified in question 1c` | `1e  Monthyear attained mmyyyy_2` |
| **c** (p2) | same + `_3` | `…attained_3` | `…field_3` | `…degreediploma_3` | `1d  Name of Country of Institution identified in question 1c_2` | `…mmyyyy_3` |
| **d** (p2) | `None_4` `High SchoolGED_4` **`Associates`** `Bachelors_4` `Master_4` `Doctorate PhD_4` `Other Degree JD MD etc_4` | `…attained_4` | `…field_4` | `…degreediploma_4` | `…question 1c_3` | `…mmyyyy_4` |
| **e** (p2) | `None_5` `High SchoolGED_5` **`Associates_2`** `Bachelors_5` `Master_5` `Doctorate PhD_5` `Other Degree JD MD etc_5` | `…attained_5` | `…field_5` | `…degreediploma_5` | `…question 1c_4` | `…mmyyyy_5` |

Four naming traps in that table, every one of which silently writes nothing:

- **Blocks d and e call the associate box `Associates` / `Associates_2`**, with an
  s, while blocks a–c call it `Associate` / `Associate_2` / `Associate_3`. The
  printed label changes too ("Associate" vs "Associate's").
- **Block b's country field has no suffix at all** — it is
  `1d  Name of Country of Institution identified in question 1c` (capital I in
  *Institution*), which differs from block a's version only by that capital.
  Blocks c/d/e then number from `_2`, so **the `_N` suffix on the country field is
  one behind every other field in the same block.**
- The degree checkbox is `Master`, singular, although the form prints "Master's".
- Every checkbox here is a plain `/On` box, not a radio group. **Tick exactly one
  per block** — nothing stops you ticking two.

**One degree per block, highest first, each one read off its own diploma.** The
failure mode on a filed form is copy-down: the bachelor's block inherits the
master's institution name and the master's month/year while carrying the
bachelor's country, so the block describes a degree that does not exist. The
intake sheet only asks for the highest degree, which is what makes the lower
blocks tempting to fill from the one above. Check each block against the actual
diploma and transcript.

Unused blocks: the firm writes `N/A` into every text field of the blocks it does
not use. That makes "left blank by mistake" and "deliberately empty"
distinguishable. Follow it.

### Section C — Training / Certifications / Licenses, three blocks (pages 2–3)

| Block | 1 provider | 1a training received | 1b certs attained | 1c start | 1d end | 1e awarded |
|---|---|---|---|---|---|---|
| a | `1 Name of InstitutionSchoolTraining provider` | `1a Name of training coursework experience received` | `1b  TrainingCertificationslicenses attained if applicable` | `1c  Start date of training mmyyyy` | `1d  End date of training mmyyyy` | `1e  Monthyear awarded mmyyyy` |
| b | `…provider_2` | `…received_2` | `1b  TrainingCertificationsLicenses attained if applicable` | `…mmyyyy_2` | `…mmyyyy_2` | `…mmyyyy_2` |
| c | `…provider_3` | `…received_3` | `1b  Trainingcertificationslicenses attained if applicable` | `…mmyyyy_3` | `…mmyyyy_3` | `…mmyyyy_3` |

**The three `1b` fields differ only in capitalisation** — `licenses`,
`Licenses`, `certificationslicenses` — and carry no `_N` suffix at all. This is
the single easiest field on the whole form to write to the wrong block. Verify by
rect with `dump --pages 2,3`, not by reading.

Block a's `1b` sits on **page 3** while its `1` and `1a` sit on page 2 — the block
straddles the page break.

### Section D — Skills, Abilities and Proficiencies, two blocks (pages 3–4)

| Block | 1 provider | 1a country | 1b state/province | 1c description (1,500 chars) |
|---|---|---|---|---|
| a (p3) | `1 Name of EmployerInstitutionSchoolTraining Provider` | `1a  Country` | `1b  State Territory or Province` | `1c Description of specific skills abilities andor proficiencies the foreign worker possesses or attained which help establish whether the foreign worker meets the requirements identified for the job opportunity up to 1500 characters` |
| b (p4) | `1 Name of EmployerInstitutionSchoolTraining Provider_2` | `1a  Country_2` | `1b  State Territory or Province_2` | **`b`** |

**Block b's description field is literally named `b`.** A one-character field name
on a 114-field form; it is a defect in DOL's PDF, and it is the name you must use.
It is also the reason a naive "find the field whose name contains *Description*"
search comes back with only one hit.

| 1b. Address 2 | `1b  Address 2` |
| 1c. City or Town | `1c  City or Town` |
| 1d. Postal Code | `1d  Postal Code` |
| 1e. Country | `1e  Country` |
| 1f. State, Territory, or Province | `1f  State Territory or Province` |
| 1g. Job Title | `1g Job Title` |
| 1h. Start Date (mm/yyyy) | `1h  Start Date mmyyyy` |
| 1i. End Date (mm/yyyy) | `1i  End Date mmyyyy` |
| 1j. Present — Yes / No | `1j  Present`, on-states `/Yes` and `/No` — **two widgets sharing one field name**, so pass `/Yes` or `/No` and let the export value pick the box |
| 1k. Hours Worked Per Week | `1k  Hours Worked Per Week` |
| 1l. Job Duties (3,500 chars) | `1l Job Duties Specify details of the job work tasks performed use of toolsequipment supervision etc up to 3500 characters` — **page 5, on its own** |

**Appendix A holds exactly one work experience.** The firm's intake sheet collects
five. Experience 2 onward goes onto Appendix C — see below. This is the structural
thing to understand about the form; everything else follows from it.

`1l` is a genuinely multiline box occupying most of page 5, but **pypdf does not
wrap**: put explicit `\n` breaks in, about 90 characters per line at that width,
and read the render.

## Appendix C — Supplemental Information (1 page, 6 fields, repeatable)

Two entry slots per sheet. Each is "which section and item this continues" plus up
to 1,500 characters.

| Slot | Section and item | Section name / category | Text |
|---|---|---|---|
| 1 | `1  Section and Item Number` | `1a Section Name or Category of Supplemental Information` | `1b Supplemental Information up to 1500 characters` |
| 2 | `1  Section and Item Number_2` | `1a Section Name or Category of Supplemental Information_2` | `1b Supplemental Information up to 1500 characters_2` |

**The firm's established pattern**, and what makes a five-job history fit a
one-job form — the item number is lettered **`E(b)`, `E(c)`, `E(d)`…**, continuing
Section E's block letters past the `a` that Appendix A itself holds, and the text
reproduces Appendix A's own 1–1l labels verbatim inside the box:

```
Section and Item Number:  E(b)
Section Name or Category: Foreign Worker Work Experience
Supplemental Information:
    Work Experience 2
    1. Employer Name: <employer>
    1a. Address 1: <street>          1b. Address 2: <suite>
    1c. City or Town: <city>         1d. Postal Code: <zip>
    1e. Country: <country>           1f. State, Territory, or Province: <state>
    1g. Job Title: <title>
    1h. Start Date: <mm/yyyy>        1i. End Date: <mm/yyyy>
    1j. Present: <Yes|No>            1k. Hours Worked Per Week: <hours>
    1l: Job Duties: <duties>
```

Two experiences per sheet; **add more Appendix C sheets for more**, rather than
compressing.

The 1,500-character cap is real and is not enforced by the fill — a long `1l`
silently overflows the visible box. Count it, and trim the job duties rather than
dropping a field.

Appendix C also takes overflow from any other section (a sixth degree, a fourth
training entry) with the same `Section(letter)` convention.

## Final Determination (2 pages)

**Page 1 is DOL-use-only and stays blank on an NIW.** Its fields exist and can be
written to; do not. They are: `1  DOL Case Number`, `2 Case Status`,
`3  Employer Legal Business Name`, `4  Employer FEIN`, `5  Foreign Workers Last
family Name`, `6  Foreign Workers First given Name`, `7  Foreign Workers Middle
Names`, `8  Job Title`, `9  SOC Code`, `10 SOC Occupational Title`,
`11  Filing Date`, `12  Determination Date`, `13  Expiration Date`,
`14  Department of Labor Office of Foreign Labor Certification electronic
signature`.

### Page 2 — three declarations

| Section | Printed | Field | NIW value |
|---|---|---|---|
| **B. Foreign Worker Declaration** | 1. Signature | `1  Signature` | **blank — the client signs by hand** |
| | 2. Date Signed | `2 Date Signed` | blank until executed |
| **C. Attorney or Agent Declaration** | 1. Last (family) Name | `1 Attorney or Agents Last family Name` | `Cai` — G-28 cases only |
| | 2. First (given) Name | `2 First given Name` | `Shenqi` |
| | 3. Middle Initial | `3 Middle Initial` | blank |
| | 4. Firm/Business Name | `4  FirmBusiness Name` | `Law Office of Shenqi Cai APC` |
| | 5. Signature | `5  Signature` | blank |
| | 6. Date Signed | `6 Date Signed` | blank |
| **D. Employer Declaration** | 1. Last (family) Name | `1 Last family Name` | the self-petitioner's family name |
| | 2. First (given) Name | `2 First given Name_2` | the self-petitioner's given name |
| | 3. Middle Initial | `3 Middle Initial_2` | |
| | 4. **Title** | `4 Title` | **`Self-Petitioner`** |
| | 5. Signature | `5  Signature_2` | blank |
| | 6. Date Signed | `6 Date Signed_2` | blank |

Section D is headed "Employer Declaration" and on an NIW the self-petitioner
signs it, with the title `Self-Petitioner`. That is the honest answer: there is no
employer designating an agent, so the beneficiary stands in that place. **Section C is filled only when the firm is
attorney of record**; on a no-G-28 case leave the whole of Section C blank.

Note the field-name asymmetry between C and D: Section C's name fields have **no**
suffix (`1 Attorney or Agents Last family Name`, `2 First given Name`) and
Section D's carry `_2` on the given name and middle initial but **not** on the
family name (`1 Last family Name`). Writing the client's surname to `1 Attorney or Agents
Last family Name` puts it in the attorney's block, and nothing warns you.

**The client's signature on page 2 Section B is a required signature page** — the
firm's Checklist calls it out by name: "ETA-9089 Final Determination - Compliant:
Page 2 Client Signature: Clear, handwritten (not electronic), and dated." Pull it
into the signature packet alongside the I-140 and G-28 pages.
