# Lingtu Data

律所只有一个数据库，Claude 里的“Lingtu Data”连接器就是它的入口。每个人用自己的律所邮箱登录，权限跟本人一样。线索、阶段、工作日志都记在这里，月底的漏斗、获客成本、bonus 业绩直接从这里算，不再看企微表格。

连不上或报“不在员工名单里”：先调 `whoami`。还不行就请 Joe 检查 staff 表。

## 总规则

1. **先查后写。** 登记、更新、回答“这个客户什么情况”之前，先用 `find` 查（编号、姓名、电话、微信号、邮箱都行）。员工一般只说人名，你按名字查出编号再操作，不要求他报编号。
2. **改动先核对，日志直接记。** 登记线索、改阶段、换对接人、写金额之前，把关键字段列给用户看，用户说对了再写。工作日志（`log_event`）不用等确认，按第零部分自动记，记完告诉用户。
3. **来源必须问客户，不要猜。** 客户确实说不记得才用“不记得了”（unknown_asked）。朋友或老客户介绍的，要问介绍人是谁。
4. **编号由系统生成。** 客户编号是 5 位随机数（如 `47765`），不按顺序，客户看不出是第几个。案件编号是 `客户编号-业务线+序号`（如 `47765-IMM1`）。企微群名、Drive 文件夹、邮件标题、Zelle 备注都带上编号。
5. **敏感信息不进库。** A 号、SSN、护照号、银行卡号一律不写。聊天全文不贴，只写一两句摘要和原件链接。
6. 下拉值不确定就调 `options`。

## 零、一个客户一个对话框，工作日志自动记

员工给每个客户开一个专属对话框。员工习惯叫客户的名字，不习惯报编号，**不要让他们改习惯**：编号只要在这个对话里出现过一次，或者你查到过一次，就是整个对话的抓手，之后员工只说人名，你自己对上编号。这样的对话框里，你负责替他记工作日志，不用等他说“记一笔”。

1. **锁定编号。** 对话标题或开头出现编号，就用它。只有人名（如标题 `王芳 婚绿`、第一句“王芳那个案子……”），先用 `find` 按名字查；只有一个匹配，直接锁定，并在回复里说一句“本对话对应 38214-IMM1 王芳”；同名或有几个案件，列出来请用户选一次。锁定后整个对话都按这个编号记，不再问，也不要求用户再报编号。
2. **人名自动对编号。** 之后用户提到这个客户的名字、昵称、英文名、配偶或家属（如“王芳老公”），都算本对话的客户。提到别的人名，先 `find` 查是不是另一个客户：是的话，那件事不往本编号下记，提醒用户去那个客户的对话框；查不到，就当作普通人名（对方律师、保险理赔员等）。员工在任何对话里说人名让你更新或查询时，也都先 `find` 按名字对编号，不要反问“编号是多少”，只有对不上或有歧义时才问。
3. **只记真发生的事。** 用户说已经做了（发了、寄了、收到了、打过电话、约好了、递交了），或者你自己用工具完成了（发出邮件、上传文件、建好案卷），就记。草稿、计划、讨论、“准备要做”的不记。
4. **当场记，不攒。** 一件事一确定就调 `log_event`，挂案件编号，没有案件编号挂客户编号，类型按第三部分选，摘要一两句，有链接带链接。递交、收据号、期限、结案要带上第三部分的结构化参数，工作台才会跟着更新。
5. **记完说一句。** 在回复最后单起一行：`已记入 Lingtu Data：<类型> · <摘要>`；工作台栏目有变的，接着写改了什么（如“递交日期 11/1，收据号 IOE0123456789”）。用户说记错了，就再记一条 `note` 写明更正哪一条（系统不能删记录）。
6. **不重复。** 同一件事只记一次。收工时只补这个对话里还没记过的。
7. **阶段、对接人、金额不自动改。** 这些照第二部分，先核对再写。
8. 敏感信息规则照旧：证件号、银行卡号不进摘要。
9. **Lingtu Data 只记里程碑和事件，细节写 Drive 的 Activity Log。** 摘要一两句：发生了什么、结论或下一步，带链接。操作细节、诊断分析、跟客户来回沟通的内容，不往库里写，写进 Drive 案卷里的 Activity Log。Activity Log 由员工自己写，你只负责替他起草，见第五部分。

## 一、新咨询登记（谁接到谁登）

1. `find` 查电话、微信号、姓名，确认不是老客户。是老客户就用他的编号（`existing_client_code`）。
2. 问齐：姓名、电话或微信（至少一个）、案件类型、简单情况、有没有截止日或开庭日、**怎么知道凌图的**。
3. 核对后调 `log_lead`，带上对接人（`owner`）。分了对接人，线索停在“待拉群”，不会自动变成“已对接”。群已经拉好的，登记时就加 `group_created=true`。
4. 工具返回客户编号和建议群名，例如 `婚姻绿卡-张三-47765`。告诉用户：企微建群就用这个名字。
5. 用户说“拉好群了”“群建好了”时，`update_lead` 带 `group_created=true`（群名和建议的不一样，再填 `wecom_group_name`），阶段这时才变成“已对接”；再用 `log_event`（`handoff`）记一笔“已拉群对接 XX”。在工作台点「已拉群」效果一样。

查重提示有相似客户时：跟用户确认是不是同一个人。是同一个人就用 `existing_client_code` 重试；不是就加 `confirm_new_client=true` 重试。

## 二、跟进阶段（对接人负责，24 小时内更新）

| 发生了什么 | 怎么记 |
|---|---|
| 企微群拉好了 | `update_lead`：`group_created=true`，阶段变“已对接”（只分了对接人、没拉群的停在“待拉群”） |
| 咨询完了（免费或 $100 / $250 / $500） | `update_lead`：`stage=consulted`；`add_note` 写一句结论；顺便给 `intent`（高 / 中 / 低） |
| 发了报价或委托方案 | `update_lead`：`stage=quoted`、`quote_amount`；再 `log_event`（`quote_sent`），`link` 放报价页链接 |
| 客户签约 | 用 `sign_lead`，见下面「签约」。不要用 `update_lead` 直接改成 signed |
| 客户不做了 | `update_lead`：`stage=lost` + `lost_reason`，必须给原因 |

### 签约（`sign_lead`）

签约要一次填齐，缺一样工具会报“签约前还缺：…”，照提示问用户补：

- 合同额；
- 付款方式：`lump`（一次付清）或 `installments`（分期，必须给 `installment_count`）；
- 主办 `lead_staff`；协办 `assist_staff`（没有可以不填）；
- 合作方：有的话 `partner` 填合作方名称、`partner_role` 填 `referral`（介绍）或 `co_counsel`（合作律师）、`partner_rate_percent` 填比例（如 40）；没有合作方就设 `no_partner=true`。John（Yue Zhang 张越）没有默认比例，按 Cindy 分案时谈好的填。

调用前把这几项列给用户核对。签完会在合同管理建好案件、出案件编号，分期进追帐管理。工作台上也一样：阶段选「已签约」会弹出签约表单，不能直接改。客户首笔律师费到账、系统自动签约的，案件在合同管理里标「待补齐」，找到它补上面几项。

流失原因只用这几个，按客户的话归类：

- 嫌贵 → `price`
- 找了别家 → `chose_other`
- 条件不够、办不了 → `not_eligible`
- 30 天联系不上 → `unreachable_30d`
- 先不办、以后再说 → `not_now`
- 不是我们的业务 → `out_of_scope`
- 都不是 → `other`，并用 `add_note` 写清楚

## 三、工作日志（谁做的事谁记）

每做完一件跟客户、案件有关的事，用 `log_event` 记一笔。有案件编号挂案件编号，没有就挂客户编号：

- 收到客户材料 → `document_received`，`link` 放 Drive 文件或文件夹
- 发出文件 → `document_sent`
- 跟对方律师、保险、法院、USCIS 的邮件 → `email`，`link` 放 Gmail 线程
- 电话、面谈 → `call` / `meeting`
- 新的截止日、开庭日 → `deadline`，同时传 `deadline_date`（YYYY-MM-DD）和 `deadline_title`（如“RFE 回复截止”“CMC 开庭”），系统会建一条期限，同一天已有的不重复建
- 递交、立案、寄出 → `filing`，传 `filed_on`（不传就按今天）；有收据号就传 `receipt_no`（3 个字母 + 10 位数字，如 IOE0123456789），不传系统也会从摘要里认 IOE/EAC/WAC/LIN/SRC/NBC/MSC/YSC 开头的号。案件阶段会从“已签约 / 办理中”自动推到“已递交”
- 结案（批准、拒绝、和解、判决、撤诉、客户终止）→ `note` 或对应类型，传 `closed_on` 和 `outcome`（approved / denied / settled / judgment / dismissed / client_terminated），案件会标成已结案
- 发帖、页面上线、案例 → `content`（可以不挂客户）

摘要写一两句：发生了什么，结论或下一步。细节不写这里，写 Drive 的 Activity Log。

**结构化参数只在挂了案件编号（`matter_code`）时生效**，工作台上的递交日期、收据号、期限、结案日会跟着自动填，已经有值的不覆盖。工具返回里 `applied` 是实际改了的栏目，`not_applied` 是没改的及原因。没改成的，告诉用户为什么（比如没挂案件编号、栏目已有值），需要的话请他在工作台手动改。

## 四、交接

用户说“交接 XX 给 YY”或“XX 现在什么情况”时：

1. `find` 查出这个客户的线索、案件和最近日志。
2. 写一段交接摘要：阶段、上次联系、待办、期限、注意事项。
3. 换对接人：`update_lead` 的 `owner` 改成接手的人，对方会收到通知。系统会自动记下谁把对接人从谁改成谁。跨部门交接后，交出去的人可能就看不到这个客户了，交接摘要要在交出去之前写完。
4. `log_event`（`handoff`）记一笔“已交接给 YY”。

## 五、收工

用户说“收工”时：

1. 回顾**这个对话**里今天做过的事，按客户归成几条。Claude Team 版看不到别的对话，所以要问用户：“今天在别的对话里还处理了哪些客户？”
2. 把整理好的条目列给用户看：客户编号、动作、一句话摘要。
3. 用户确认后，逐条 `log_event`；阶段变了的同时 `update_lead`。
4. 再按客户各起草一段 Drive Activity Log 的文字，放进代码框方便复制。格式照案卷里已有的写法：日期、谁、做了什么，加上细节（按了什么、查到什么、判断依据、客户怎么说、下一步）。比库里的摘要写得细。不要自己去改 Drive 文件，由员工核对后贴进去。
5. 最后报一句：今天记了几条、哪些客户还缺编号或来源、哪几段 Activity Log 等他去贴。

## 跟其他 skill 的衔接

- `/consult` 归档完咨询 → 回到第二部分，把阶段改成“已咨询”。
- `/quote` 出完报价页 → 改成“已报价”，金额和链接写进去。
- `/it` 建完案卷 → `link_case_folder`（`matter_code` 或 `client_code` + `drive_folder_url`）把 Drive 案卷挂到案件上。/it 建文件夹前先用 `find` 拿客户编号和案件编号，文件夹名后面加「 - 客户编号」。
- Drive 案卷里的 Activity Log 照写，管细节；Lingtu Data 管里程碑和事件。两边不冲突，也不互相替代。
- 拉群对接 → 先做第一部分拿到编号，再建群。
