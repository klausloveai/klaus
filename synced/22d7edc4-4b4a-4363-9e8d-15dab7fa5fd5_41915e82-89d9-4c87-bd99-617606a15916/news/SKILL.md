# news — 华裔/移民新闻双稿生成器

每次运行分四阶段：**调研 → 选题 → 双稿成稿并存档 → 官网草稿 + 媒体版，通知用户检查**。

每期产出两份文件：
- **口播稿**：1.5分钟视频口播，社交媒体风格
- **新闻稿**：500–700字，华文报章风格，含律师评语

---

## 阶段一：新闻调研

用 WebSearch **同时**运行以下三组关键词（都要搜，不要只搜一组）：

1. `Chinese Americans Asian Americans news policy 2026` + 当前月份
2. `immigration policy reform USCIS executive order 2026` + 当前月份
3. `亚裔 华裔 移民 新政策 2026` + 当前月份

对每条候选新闻用 WebFetch 读取原文，提取：
- 事件时间线（什么时候发生/生效）
- 关键数字（影响人数、金额、百分比、截止日期）
- 官方来源（机构名、法案编号、发言人姓名+职务）

如有用户提供的线索（URL、截图、案例描述），优先以此为素材，再补搜核实。

**查重（必须做，选题前完成）：**

先看最近 14 天做过什么，避免重复选题：

1. 口播稿根目录 `1EqS3nWX9RSZP8grTm1ayZYc5R3l3MkrH` 下最近几期的日期子文件夹，看里面的文件名。
2. 「新闻稿」文件夹 `1asvRIWVcKiFrDnQDchJ-pDxa49eE2sYh` 里的文件名。
3. 官网 `posts` 表最近的文章：`select slug, status, published_at, title from posts order by published_at desc limit 10;`（Lovable 项目 `3beabb73-f7ca-4a0c-b860-6d92843f3046`，用 `query_database`）。

只看文件名判断不了内容时，把旧稿导出来读。注意 `gws ... export` 的 `-o` 只能写到当前目录，给绝对路径会报错，要先 `cd` 到目标目录再写相对文件名：

```bash
cd <scratchpad目录> && gws drive files export --params '{"fileId":"<DOC_ID>","mimeType":"text/plain"}' -o old.txt
```

判断规则：
- 同一政策、同一角度已经写过 → 换题。
- 同一政策但有了新进展（生效、起诉、法院裁定、新数据）→ 可以写，但要换角度，正文只简单交代前情，重点写新进展，并在报告里告诉用户"这是 X 月 X 日那期的后续"。
- 发布后可提议在旧文末尾加「后续报道」链接（见阶段四）。

**来源数字不一致时：**

同一个数字（人数、州数、金额、日期）在不同报道里说法不同，很常见。处理方法：
1. 至少对照 3 个来源，优先顺序：官方原文（机构公告、法院文件、总检察长新闻稿、《联邦公报》）→ 主流媒体（Reuters、AP、CNN、世界日报）→ 律所博客、自媒体。
2. 能自己核算的就自己核算，比如按新闻稿里列出的州名数一遍。
3. 选最有依据、最说得通的那个写进稿子，措辞按原文准确表达（例如"纽约州联合另外20州、华盛顿特区及宾州州长"，而不是笼统写"21州"）。
4. 在报告里告诉用户哪个数字有分歧、各来源怎么说、最后选了哪个和理由。
5. 实在定不下来的，删掉，换一个能核实的数字（见错误处理）。

**新闻优先级排序：**
1. 直接针对华裔/亚裔的事件（歧视、攻击、社区政策、签证/移民局专项行动）
2. 对移民群体有重大影响的全族裔政策（移民法改革、USCIS、ICE、劳动法、教育政策）
3. 经济/就业政策中与工签/绿卡群体相关的部分

选出**一条**影响最大、数据最充分的新闻作为本期主题。两条同等重要时可做合集，但口播稿须保持在 1.5 分钟内。

## 阶段二A：口播稿

口播稿**严格控制在 380–420 字**（普通话口速约 250 字/分钟，1.5 分钟上限）。字数算法见下方「字数怎么算」。

### 字数怎么算

两稿的字数**只数汉字**：标点符号不算，英文字母和阿拉伯数字也不算。用这个脚本数（先去掉【开场钩子】这类结构标签，新闻稿不算标题行）：

```bash
python3 -c "import re,sys; t=open(sys.argv[1]).read(); t=re.sub(r'【[^】]*】','',t); print(len(re.findall(r'[\u4e00-\u9fff]',t)))" <文件>
```

报告和 Doc 末尾写的「字数：X 字」都用这个数。

### 固定结构（按顺序，不可跳过）

```
【开场钩子】5–8 秒
用一个让人停住的数字或反问句开头。
格式：「[令人震惊的数字或情境] ——这不是假设，是[本周/刚刚]生效的新规。」

【事件概述】15–20 秒
2–3 句话说清楚：什么事、谁发起/宣布、什么时候生效。
不用背景铺垫，直接讲核心。

【关键数据】20–25 秒
3 个具体数字，每个单独成句：
• 数据 1：规模/影响人数/金额
• 数据 2：时间线/截止日期/比例
• 数据 3：历史对比或来源权威性

【华裔移民影响分析】40–45 秒，≥2 点，每点精准具体
格式：
影响一：[具体是什么] → 尤其是 [精确人群，如"持H-1B转绿卡过程中签证到期的工程师"/"F-1期间有过LOA未及时离境的学生"]。
影响二：建议 [具体行动：在XX日期前做X、联系移民律师确认X、查清X记录]。

【结语 + 互动引导】10–12 秒
1 句总结 + 1 句引导评论/关注。
格式：「[一句话点题]。你或你身边的人受到影响了吗？评论区说一声，帮忙转给需要的朋友。」
```

### 写作要求

- 口语化，不要书面腔
- 数字用阿拉伯数字（300万、$5000），不用大写汉字
- 政策名称第一次出现给中文解释：「H-1B（工作签证）」
- 不用"据悉"、"相关部门"，必须说出具体机构名称
- 具体人群要精确：不说"很多华人"，要说"2020年后申请绿卡的华裔家庭"

## 阶段二B：新闻稿

新闻稿**字数 500–700 字**（只数汉字，不算标题、标点、英文和数字，见阶段二A「字数怎么算」），模仿《世界日报》/洛杉矶华人资讯网的华文报章风格。

### 固定结构

```
【标题】
直接、有新闻价值。含核心事件 + 结果/影响。
- Breaking 新闻：【独家】/【突发】+事件+结论
- 政策报道：[受影响群体] + [政策内容] + [影响/后果]
- 例：「F-1签证新规九月上路 在读博士须主动延期 30天Grace Period令留学生措手不及」

【导语】
格式：「本报[日期]报道，（本报讯）[开门见山说核心：谁/什么/在哪/何时/结果]。」
第一句话就是最重要的事实。不铺垫，不过渡。

【正文】（2–3个小标题分节）
小标题格式：加粗，3–8字，直接说该节核心
每节：事实陈述 → 官方引语（机构全称 + 发言人姓名 + 职务 + 直接引语）→ 背景数据
数字精确到个位。直接引语用书名号「」。

【律师评语段】（必须包含，放在倒数第二段）
格式：
「凌图律所资深律师蔡沈祺表示/建议，[第一个具体建议，精确到行动步骤]。此外，[补充建议]。」
「蔡律师指出/强调，[进一步说明，第二个法律要点]。」

律师评语规范：
- 第一次出现用全名：蔡沈祺
- 后续引用：蔡律师 / 蔡沈祺
- 建议必须具体可操作：不说"要注意"，要说"建议在[X日期]前向DSO提交[X材料]"
- 不做没有依据的法律预测
- 如果案例来自律所实际接案，可说：「凌图律所本周接到多起类似咨询」

【结尾】
一句话说明对华裔社区的实际处境或下一步走向。纯事实，不做任何"联系我们"式引导。

【版权行】
「（本报讯）」
```

### 写作要求

- 正式书面语，非口语（与口播稿区分）
- **不写营销内容**：不出现"联系凌图"、"欢迎咨询"、"原创供稿"等任何推广语。律师是作为新闻来源被引用，不是广告主。
- **只写7天内新闻**：选题必须是发布/生效日期在7天以内的事件；超期的旧闻不写新闻稿（口播稿不受此限制，可补写）
- 官方机构名称全称首次出现，括号标注简称：「美国移民局（USCIS）」
- 引用数字来源可核实，不编造
- 律师评语不得虚构法律后果，只说已有依据的内容
- 案例细节（当事人）完全匿名处理

## 阶段四：官网草稿 + 媒体版（写完通知用户检查）

新闻稿存档后，在后台把它写成官网**草稿**，同时生成媒体版 Doc，然后通知用户检查。**只写草稿，不直接上线**；上线由用户审完后决定。

### 官网怎么运作（先弄清楚再动手）

- 官网 https://www.lingtulaw.com 是 Lovable 项目 `3beabb73-f7ca-4a0c-b860-6d92843f3046`。文章不在代码里，存在该项目 Supabase 数据库的 `posts` 表，线上网站直接读这张表。
- 文章上不上线**只看 `status` 字段**：`published` 写进去官网立刻出现；`draft` 线上返回 404。Lovable 编辑器里的 Publish 按钮只管代码，跟文章无关。
- 用 Lovable 连接器的 `query_database` 直接写表。**不要**用 `send_message` 叫 Lovable 的 AI agent 去发文章：它会耗 credits、可能改到代码，还可能直接写成 `published`。
- 文章网址：`https://www.lingtulaw.com/news-firm-updates/<slug>`

### 步骤 4.1 — 查重

```sql
select slug, status, title from posts where title = $pc$<新闻稿标题>$pc$;
```

已有同标题记录就不要再插，直接告诉用户已有的 slug 和状态。

### 步骤 4.2 — 写入草稿

字段对照（照已发布文章的格式）：

| 字段 | 写法 |
|------|------|
| `slug` | `insights-YYYYMMDD-<6位小写字母数字随机串>`，日期用本期新闻稿日期 |
| `category` | `insights`（政策解读）；律所自身动态（开业、活动、获奖、媒体报道）用 `firm-news` |
| `title` | 新闻稿标题 |
| `body_md` | 新闻稿正文：导语去掉「（本报讯）」，即以「本报X月X日报道，」开头；加粗小标题改成 `### 小标题`；段落之间空一行；去掉文末版权行 |
| `excerpt` / `seo_description` | 导语第一句，去掉「本报X月X日报道，」 |
| `seo_title` | `<标题> \| 凌图律所法律时事解读` |
| `source_line` | `新闻来源：<机构> <日期> · <URL（去掉 https://）>`，列 1–2 个官方原文 |
| `lang` | `zh` |
| `status` | **`draft`** |
| `published_at` | `'<本期日期> 00:00:00+00'` |

文本字段一律用 `$pc$...$pc$` 包起来，避免引号转义出错。结尾加 `returning id, slug, status`，把返回的 id 和 slug 记下来。

### 步骤 4.3 — 确认草稿没有外泄

```bash
curl -s -o /dev/null -w '%{http_code}\n' -L https://www.lingtulaw.com/news-firm-updates/<slug>
```

应该返回 404。如果返回 200，说明写成了已发布，立刻把 `status` 改回 `draft`，并告诉用户。

### 步骤 4.4 — 媒体版 Doc

在「媒体新闻稿」文件夹 `1DzjV_5l6BKSv1jVUbYISm2eu3m-JtyvT` 里建 Google Doc，文件名 `媒体版 新闻稿 <YYYY-MM-DD> <媒体版标题>`。这份是直接发给《世界日报》/ ChineseInLA / 城市新闻网编辑的版本，编辑会整段复制进他们的后台（后台支持加粗和改字体颜色），所以版式要做到拿来就能用。

**1. 先写纯文本**，内容按这个格式：

```
【供稿单位】凌图律师事务所 Lingtu Law APC（洛杉矶县工业市）
【发布日期】<YYYY-MM-DD>
【转载说明】欢迎媒体全文或摘录转载；引用律师观点请保留“凌图律所资深律师蔡沈祺”署名。
【媒体联系】info@lingtulaw.com · +1 (415) 547-9999 · 微信 lingtulaw
【律所简介】凌图律师事务所位于洛杉矶县工业市，中英双语，主办职业移民（EB-1A、NIW、O-1、H-1B、L-1）、婚姻绿卡、人身伤害、民商事诉讼及信托遗嘱。创始人蔡沈祺律师为加州执业律师（#348794）。

——————————————————————————————

<媒体版标题>

<新闻稿正文，保留导语里的「（本报讯）」，小标题单独成行>

（本报讯）

<附表文字版（如有），供编辑核对数字>

信息来源：
<官方原文 URL，每行一个>
```

**2. 媒体版标题要短、要劲爆**（媒体编辑的建议：标题简短劲爆，关注量更高）：
- 约 12–20 个汉字，最多一句加一个短尾，不要三段式长标题。
- 把最抓人的数字或结果放在前半句，用"一口气""狂跳""抢先""恐遭""全面"这类有力度的动词和副词。
- 劲爆不等于夸大：意思必须和正文一致，不能把"递件日前进"写成"批卡提前"，也不能把"可能"写成"一定"。
- 例：`10月移民排期出炉 中国大陆出生EB-3递交日跳进814天 移民局准按表B递交I-485` → `大陆EB-3递件排期一口气跳814天 10月就能交I-485`。
- 官网草稿（`posts.title`）和「新闻稿」文件夹里的原稿仍用阶段二B的标准标题，只有媒体版换成这个短标题。

**3. 再加格式**（用 `gws docs documents batchUpdate`，先 `documents get` 拿 `revisionId` 放进 `writeControl.requiredRevisionId`，请求从高索引往低索引排；中文字符按 UTF-16 算都是 1 个单位）：
- 标题：`HEADING_1` + 加粗。
- 小标题：`HEADING_2` + 加粗 + 红色 `#B3261E`。
- 关键句：每篇挑 3–6 处加粗，包括最重要的数字、生效日或截止日、官方确认的结论、律师给出的具体行动建议。其中**只有最核心的那一句**同时加红色 `#B3261E`。颜色只加在短语上，不整段上色。
- 附表文字版的分组标题加粗。

**4. 时间表、排期表、数字对比、时间线一律做成配图**（媒体编辑的建议：图片比文字更吸睛）：
- 用 HTML 画一张 1080px 宽的信息图，用 Chrome 无头模式按 2 倍截图：
  `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=2 --window-size=1080,<高度> --screenshot=<out>.png file://<html>`
  先用 1 倍截一张，用 Read 看一下有没有溢出、截断或底部空白过多，调好再出 2 倍的正式图。
- 配色用律所品牌色：羊皮纸底 `#FAF6EC`、墨色字 `#1C1A17`、金色 `#A8862F`/`#C0A260`，高亮用红色 `#B3261E`。中文字体用 PingFang SC。
- 图里要有：醒目的大标题（突出核心数字）、对比表或时间线、一句话说明，底部标注「资料来源：<机构>」和「制图：凌图律师事务所」。数字必须和正文、附表完全一致。
- 上传到「媒体新闻稿」文件夹，文件名 `配图 YYYY-MM-DD 主题.png`（`gws drive files create --upload <png> --json '{"name":…,"parents":["1DzjV_5l6BKSv1jVUbYISm2eu3m-JtyvT"]}' --params '{"supportsAllDrives":true}'`）。
- 插入文档：Docs API 只能从公开网址取图，所以先给这张 PNG **临时**开"知道链接的人可查看"（`gws drive permissions create`，`{"type":"anyone","role":"reader"}`），再用 `insertInlineImage`（`uri` 为 `https://drive.google.com/uc?export=download&id=<图片ID>`，宽 450pt，高按比例算）插在正文「（本报讯）」之后、附表文字版之前（先插一个 `\n` 空段落，再在该位置插图）。插完**立刻删除**这个 `anyoneWithLink` 权限，并用 `permissions list` 确认只剩账号内用户。图片插进去以后是复制进文档的，撤销权限不影响显示。
- 附表文字版保留在图下面，方便编辑核对和复制数字。

**5. 检查**：再 `documents get` 一次，确认标题和小标题的样式、加粗范围和红色范围都对，`inlineObjects` 里有这张图；导出 PDF（`gws drive files export … application/pdf`，`-o` 只能写相对路径），用 `qlmanage -t -s 1200 -o <目录> <pdf>` 生成首页缩略图，用 Read 看一眼版面。

### 步骤 4.5 — 通知用户检查

草稿和媒体版都写好后，通知用户（如果有 `PushNotification` 工具就推送一条，用户不在电脑前也能收到；同时在最终报告里写明）：

- 官网草稿：标题、slug、状态 `draft`、线上目前 404（确认没外泄）
- 媒体版 Doc 链接
- 请用户（或蔡律师）核对：标题、数字和日期、机构与人名、律师评语是否准确
- 发布方式：用户回复"发布"后，执行 `update posts set status = 'published' where id = '<id>'`，再用 curl 确认返回 200；用户也可以在 Lovable 编辑器 Cloud → Database → `posts` 表里自己改

发布之后：如果之前有同一主题的旧文章，问用户要不要在旧文末尾加一行 `**后续报道：**[<新标题>](/news-firm-updates/<新slug>)`。**新文章发布之前不要加**，否则读者点进去是 404。

### 规则

- 新闻稿正文本身不变（阶段二B 的"不写营销内容"规则继续有效）；供稿信息只出现在媒体版头部和官网文末的来源行。
- 没有用户明确同意，不写 `status = 'published'`，也不改已发布的文章。
- 不对 `posts` 表执行 `DELETE`。需要删除时，告诉用户记录的 id，请用户自己在 Lovable 里删。
- 口播稿不上官网。
- Lovable 连接器不可用时，照常完成阶段一到三和媒体版，明确告诉用户"官网草稿待连接"，不要静默跳过。

## 世界日报笔锋速查

从 ChineseInLA/世界日报 实际报道中提取的写作规律：

| 要素 | 格式 |
|------|------|
| 导语 | `本报X月X日报道，（本报讯）[核心事实一句话]。` |
| 小标题 | 加粗，3–8字，点明该节核心，不用句号 |
| 官方引语 | `[机构全称][发言人姓名]表示，「[直接引语]」` |
| 律师首次引用 | `凌图律所资深律师蔡沈祺表示/建议，[内容]。` |
| 律师后续引用 | `蔡律师指出，[内容]。` 或 `蔡沈祺强调，[内容]。` |
| 数字 | 精确到个位（161万美元、8,000份、60天），不用约数 |
| 社区视角 | 最后一段回到华裔社区的具体处境和行动建议 |
| 版权行 | 文末单独一行 `（本报讯）` |

## 错误处理

| 情况 | 处理方式 |
|------|----------|
| 搜不到 7 天内相关新闻 | 扩展到 14 天，说明日期 |
| 找到多条同等重要新闻 | 选影响华裔最直接的那条；其余在结语里一句带过 |
| 某条数据无法核实 | 删掉，换其他可核实的数据，不编造 |
| 不同来源数字打架 | 对照至少 3 个来源，优先官方原文，选最合理的写，并在报告里说明分歧（见阶段一） |
| 律师评语无法确认法律依据 | 改为"建议咨询专业律师"，不捏造具体结论 |
| Drive 存档失败 | 先把两稿全文输出给用户，再说明存档失败原因 |
| 官网草稿写入失败 | 媒体版照做；把错误原文告诉用户，不要改用 `send_message` 让 Lovable agent 代发 |
