# 归档结构与命名

## 三层结构

```
1. Initial/
  0. 个人信息/
    护照首页-Qing Yang.pdf
    签证页-F1-Qing Yang.pdf
  1. Awards 奖项/
    ✅ iF Design 2026 - Sofia/
      奖状-iF Design 2026 Sofia.pdf
      获奖页面-ifdesign.com-20260304.pdf
    红点 2026 - Sofia/
      获奖通知邮件-红点 2026-20251015.pdf
  4. Judging 评审/
    ✅ Orpetron/
      邀请函-Orpetron-20250612.pdf
      官网listing-Orpetron 评委页.pdf
      打分表-Orpetron-sample10.pdf
      证明信-Orpetron certificate.pdf
```

**条件文件夹**（第一层）由 `scan_materials.py layout` 建，名字和
skye-case-drive 在 `3. Petition Letter & Exhibits` 里建的条件文件夹一字不差，
只多一个前缀编号。两棵树对得上，写 exhibit 时「这条标准的原始材料在哪」看名字
就知道，不用记映射。编号是因为 Drive 按字母排序，不编号「高薪」会排在「奖项」
前面，和材料清单的顺序对不上。

**条目文件夹**（第二层）= 材料清单里的一个一级条目。名字和清单里的条目行保持
一致，这是清单和 Drive 之间唯一的对照关系：

```
{对象} {年份}                 红点 2026
{对象} {年份} - {作品}        iF Design 2026 - Sofia
{对象}                        Orpetron、凤凰网、SUNY Fredonia
```

证据收齐后在文件夹名前加 `✅ `（律所现有案子就是这么标的，见 Qing Yang 的
`✅ Orpetron`、`✅ WBDS Award`）。同一件事在清单里也打 `✅`，两边同步。

条目文件夹**只在有材料时建**。空文件夹让人以为材料已经在了，比没有更糟 ——
「还没收到」这件事由材料清单负责表达。

## 文件命名

```
{证据类型}-{简述}-{YYYYMMDD}.{ext}
```

- **证据类型**取自下表，是这套命名唯一的固定部分。同一条目里的文件按类型排序，
  一眼看出邀请函有了、打分表还没有。
- **简述**可省；用来区分同类型的多份（`打分表-Orpetron-sample10`）。
- **日期**是文件本身的日期 —— 签发日、发布日、签字日，**不是上传日期**。
  移民官关心的是证据发生在什么时候，上传时间没有意义。没有日期的就不写。
- 中文文件名可以，律所现有卷宗大量是中文名。不要为了「规范」翻成拼音。

| 章节 | 证据类型 |
|---|---|
| 个人信息 | `护照首页` `签证页` `I-94` `I-20` `I-797` `个人信息表` `结婚证` `配偶护照` `简历` |
| 奖项 | `奖状` `获奖通知邮件` `获奖页面` `评选标准` `评选通知` `红头文件` `奖项介绍` |
| 会员 | `会员证书` `会员页面` `入会标准` `审核通过letter` |
| 新闻 | `报道` `报道截图` `纸媒扫描件` `翻译件` `媒体介绍` |
| 评审 | `邀请函` `官网listing` `证明信` `打分表` `评审记录` `节目单` `获奖名单` |
| 原创贡献 | `专利` `论文` `书籍扫描件` `课程页面` `使用证明` `引用证据` `标准文件` |
| 学术发表 | `论文` `期刊页面` `录用通知` `会议摘要` `发行量资料` |
| 展览 | `邀请函` `参展证明` `现场照片` `展览页面` `作品说明` |
| 重要组织重要角色 | `offer` `雇佣证明` `promotion letter` `job description` `推荐信` `公司资料` `项目材料` |
| 高薪 | `W2` `paystub` `offer` `薪资对比数据` |
| 身份材料（O-1） | `I-797` `paystub` `身份时间线` `旅行记录` |
| 工会信 | `Consultation Letter` `推荐人资料` |
| 未来计划 | `offer` `Personal Statement` `Business Plan` `authorization letter` |

表里没有的用最贴切的中文名词，别硬塞进 `MISC`。这些文件后面要变成 exhibit，
名字本身就是 index 的草稿。

## 复制，不是移动

客户传到 `0. Shared Folder` 的原件**原地不动**，归档进 `1. Initial` 的是副本。
那个文件夹是客户自己的空间，他们会回去找自己传过什么；文件在他们眼皮底下改名
消失，下一步就是微信里问「我传的东西呢」。

只有一种情况是移动（`op: "move"`）：文件本来就在 `1. Initial` 里 —— 建 case
时直接丢进去的那批 —— 那本来就是律所这边的树，改名归位即可。

## 已归档的判定

每个副本都带 `appProperties.eon_src` = 客户原件的 file id。第二次以后只处理
`0. Shared Folder` 里 id 不在这个集合里的文件。

不能靠文件名比对：第一次运行就把名字全改了，之后每次比对都会认为全是新的，
把整个卷宗再复制一遍。

## 不要归档的东西

`Intake Note - *`、`材料上传指引邮件 - *`、`Document Upload Instructions - *`
是律所自己生成的文档，不是客户材料。`inventory` 会把它们单独列在
`generated_docs` 里 —— intake note 要读（里面有 DDL、身份状态、案件背景，写清单
头部要用），但不要归进条件文件夹。
