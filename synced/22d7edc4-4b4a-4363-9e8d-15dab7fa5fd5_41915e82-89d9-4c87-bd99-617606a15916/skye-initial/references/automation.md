# 自动化任务的运行、收件人与失败模式

## 收件人

全部在 `scripts/notify.py`，改那一个文件。

| 组 | 收件人 | 什么时候发 |
|---|---|---|
| `new-materials` | kk@, cathy.c@, skye.s@ | 每日巡检发现新上传 |
| `progress` | kk@, cathy.c@ | 材料进度表更新后 |
| `meeting` | skye.s@（抄送 cassie@） | 排出候选时段，请 Skye 确认 |

`notify.py` 对非 `@lingtulaw.com` 的地址硬拒。**客户话术一律只打印不发送。**

### 地址上的两个坑

- **Skye 是 `skye.s@lingtulaw.com`。** `skye@lingtulaw.com` 不存在。域内命名是
  「名 + 姓首字母」：`cathy.c@`、`karina.y@`、`skye.s@`。例外是 `kk@` 和
  `cassie@`，这两个是短地址。
- 拿错地址查日历不会报错到你脸上：freebusy 返回 `notFound` 加一个**空的 busy
  列表**，只看 busy 的话就是「这人全天有空」。`meeting.py` 因此把任何单个日历的
  错误当成致命错误，一个时段都不给。

## 定时跑每日巡检

脚本自己不带调度。在实际要跑它的那台机器上挂一个：

```bash
python3 ~/lingtu-skills/skye-initial/scripts/daily_sweep.py
```

装在谁的电脑上，就用谁的 gws 账号发信和读日历。摘要收件人不随之改变，所以从
Skye 电脑上跑出来的巡检一样会发给 KK。

跑之前先手动跑一次 `--dry-run` 看摘要内容对不对，再挂上去。

## 状态文件

`~/.local/state/skye-initial/sweep_state.json`，可用 `EON_STATE_DIR` 改位置。
记录每个案子已经报过的 file id。

- 删掉它不会坏事：下一次把当前所有待归档的当成新的报一遍。
- 换机器不会同步。两台机器各跑巡检，会各报各的一遍。要么只在一台上挂定时任务，
  要么接受重复。

## 各脚本的失败方式

| 脚本 | 失败时 | 表现 |
|---|---|---|
| `daily_sweep.py` | 某个案子文件夹读不到 | 该案进 `skipped`，摘要里单列，其余案子照常 |
| `daily_sweep.py` | 案件总表 H 列没链接 | 同上，摘要里写明「没有可用的文件夹链接」 |
| `meeting.py slots` | 任一日历读不到 | 退出码 2，不给任何时段 |
| `case_number.py scan` | 信箱里没有 | 报「没找到」，并注明可能在同事信箱里 |
| `case_number.py apply` | 客户名匹配到多行 | 列出候选行，不写表 |
| `case_number.py apply` | 号码格式不对 | 拒绝写入 |

`case_number.py apply` 只**追加** F 列，不覆盖。F 是人手写的重要笔记，覆盖会
悄悄删掉同事的内容 —— 等到需要那条笔记时才会发现。

## 时区

律所 `America/Los_Angeles`，客户 `Asia/Shanghai`。律所能约会议的时间是
**美西 09:00–17:30**。

时差夏令时 15 小时、冬令时 16 小时，这一小时的差别决定了能不能排出会：

| | LA 09:00–17:30 = 北京 | 一小时的会 |
|---|---|---|
| PDT（约 3 月–11 月） | 次日 00:00–08:30 | 和北京 08:00–22:00 **没有重合**（LA 16:30 才到北京 07:30） |
| PST（约 11 月–3 月） | 次日 01:00–09:30 | LA 16:00–17:00 = 北京次日 08:00–09:00 ✅ |

夏天必须放宽一边。`meeting.py` 在零结果时会自动把下面几种各试一遍并报数量，
顺序是先动客户那边 —— 请北京客户 07:30 开会，比请两位律师留到 17:30 之后是更小的
人情：

| 放宽方式 | 参数 | 得到的时段 |
|---|---|---|
| 客户 07:00 起 | `--cn-window 07:00-22:00` | LA 16:00–17:00 = 北京次日 07:00–08:00 |
| 客户 06:30 起 | `--cn-window 06:30-22:00` | LA 15:30 起 |
| 律所延到 18:00 | `--la-window 09:00-18:00` | LA 17:00–18:00 = 北京次日 08:00–09:00 |
| 律所延到 19:00 | `--la-window 09:00-19:00` | 最宽松 |
| 律所 07:00 开始 | `--la-window 07:00-17:30 --cn-window 08:00-23:00` | LA 07:00 = 北京**当晚** 22:00 |

最后一行是唯一不跨日的选项，别把它和其余几行混着写日期。

### 话术

时间写「上午/下午/晚上 + 几点」，不写裸的「6点」—— 可用时段集中在律所下午和客户
清晨，12 小时制不带上下午会把两边差出 12 小时。半点的时段要带分钟。

**两地日期都写全**，不管差不差。律所下午对应客户次日清晨，几乎每个方案两个日期
都不一样；只写一个日期是客户晚到 24 小时最常见的原因。

```
09/14/2026 洛杉矶时间下午4点，客户当地时间09/15/2026（次日） 上午7点，您是否有空，我们约个会议，对一下材料；
```
